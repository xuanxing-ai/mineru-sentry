# 原始内容保留接口

`POST /api/v1/parse/faithful` 是独立于原 MinerU 任务缓存的新接口。原 `/api/v1/parse` 接口继续保留。

## 请求与结果

使用 multipart 表单上传：

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `file` | 文件 | PDF 或 DOCX；旧版 DOC 必须先另存为 DOCX |
| `ocr` | 布尔值，默认 `true` | 遇到扫描页时调用本地 MinerU。设为 `false` 时，扫描页返回错误，不会被当成空白页跳过 |

响应正文为 UTF-8 Markdown，可包含 HTML 段落、上下标和合并单元格表格。图片相对路径指向 `images/`。

响应头 `X-Sentry-Artifact-ID` 标识本次结果。调用 `GET /api/v1/parse/faithful/{artifact_id}/zip` 下载完整包，包含 `result.md`、`images/` 和 `report.json`。单独保存响应文字不会下载图片，应优先保存完整包。

每次请求使用新的结果目录，不复用原 MinerU 缓存，不删除原有任务。原生 Word/PDF 提取无需数据库或 GPU；扫描页使用已有 GPU 服务及其超时、共享输出目录配置。

## 内容处理

- DOCX 直接读取原始 XML，保留正文顺序、表格合并、上下标、内嵌图片及页眉页脚。页眉、页脚、脚注和尾注按部件另行保留，不重建 Word 分页。
- PDF 逐页读取文本层，按字符位置还原表格和常见双栏顺序；拆成细条图片的符号重新合并，图片放回内容中。每页还附带原始页面截图。
- 扫描页使用 `hybrid-engine`、`effort=high`、`parse_method=ocr`，保留 OCR 图片及整页原图。OCR 错字不会被擅自猜测修改。
- 缺失图片、原生字符丢失或重复、非空页面 OCR 无结果时，不发布成功结果。暂不支持的 Word 自动编号会明确报错。

## 如何理解校验报告

`parts` 逐页或逐 Word 部件记录提取方式、原生非空白字符数量、输出字符数量、表格数量和待核验事项。原生字符校验比较字符及出现次数，能发现遗漏或重复，**不能证明阅读顺序、表格关系或 OCR 正确**。

`requires_review` 和响应头 `X-Sentry-Review-Required` 始终提示需要核验。HTTP 200 表示提取及打包完成，不表示所有内容已经人工校对。

Markdown 无法完整重现 Word/PDF 的分页、签章、字体及任意复杂公式布局。公式和图片应结合保留的原图核对。扫描件无法通过配置保证零错字；涉及金额、编号、日期、符号、签字等内容时，必须对照原件检查。

## 测试脚本

`tests/test_fidelity.py` 调用保真接口，并校验完整结果包。输出按原文件名和测试产物分别保存。

修改代码后，需要安装更新的项目依赖并重建或重启网关服务，运行中的旧容器不会自动增加新接口。

实际文件回归测试通过 `SENTRY_FIDELITY_TEST_INPUT` 指定原件目录。原件和输出必须保存在 Git 忽略路径，不加入版本库。
